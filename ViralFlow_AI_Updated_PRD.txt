ViralFlow AI — Updated Product Requirements Document (PRD)

Autonomous AI Content Discovery, Creation, Editing, Publishing & Learning Platform

Hackathon: Separate / non-Alibaba hackathon
Category: Open Innovation
Primary automation: n8n + low-code/no-code
Development: Claude + Antigravity + OmniRoute
Alibaba dependency: None

------------------------------------------------------------------------

1. Executive Summary

ViralFlow AI is an autonomous content-operations platform for creators.

Instead of being only an AI script writer or AI video generator,
ViralFlow continuously:

Finds opportunities → analyzes them → decides what the creator should
make → writes the content → gathers/generates media → edits the video →
publishes it → measures performance → learns what worked.

The goal is to give an individual creator an AI content team consisting
of:

-   Trend researcher
-   Content strategist
-   Scriptwriter
-   Fact checker
-   Producer
-   Video editor
-   Publisher
-   Performance analyst

The main differentiator is the closed feedback loop.

  Discover → Analyze → Decide → Create → Edit → Publish → Measure →
  Learn

------------------------------------------------------------------------

2. Problem

Creators spend significant time on:

-   Finding trends
-   Understanding why a topic is becoming popular
-   Deciding whether a trend fits their audience
-   Writing hooks and scripts
-   Finding B-roll
-   Recording voice/avatar footage
-   Editing
-   Adding captions
-   Publishing
-   Checking analytics
-   Deciding what to make next

Most existing AI tools automate only one or two of these steps.

ViralFlow aims to connect the entire process.

------------------------------------------------------------------------

3. Product Vision

Build an always-on AI content operator that can take a creator profile
and continuously produce relevant short-form content opportunities,
prepare videos, publish them with authorization, and learn from
performance.

5. Goals

P0 Goals

1.  Automate trend discovery.
2.  Score trends based on momentum and creator fit.
3.  Create original content angles.
4.  Generate scripts and structured scene plans.
5.  Retrieve stock media.
6.  Generate selected AI visual scenes when useful.
7.  Produce voice/captions.
8.  Automatically assemble vertical videos.
9.  Publish or prepare videos for publishing.
10. Collect analytics.
11. Learn from results.

Non-Goals

-   Guaranteeing virality.
-   Training a foundation video model.
-   Building a professional Premiere Pro replacement.
-   Scraping every social platform.
-   Publishing without user authorization.
-   Reproducing another creator’s content.

6. Creator DNA

Creator DNA is a structured profile describing how a creator normally
produces content.

It should contain:

-   Niche
-   Target audience
-   Country/market
-   Language
-   Tone
-   Vocabulary
-   Average video length
-   Preferred hook types
-   Preferred topics
-   Topics to avoid
-   Visual style
-   Caption style
-   Brand rules
-   CTA style
-   Historical successful topics
-   Historical successful hooks
-   Historical performance patterns

Example:

    {
      "niche": "AI and technology",
      "audience": "Pakistani university students",
      "language": "English",
      "tone": ["fast", "educational", "direct"],
      "duration": "30-60 seconds",
      "hook_style": ["question", "surprising fact"],
      "cta_style": "short",
      "avoid": ["political controversy"]
    }

Creator DNA should be versioned so the system can learn over time.

8. IMPORTANT: How Everything Connects Through n8n

n8n is the central orchestration layer.

Do not make every service directly communicate with every other service.

Instead:

    Service A
        ↓
    n8n
        ↓
    Service B
        ↓
    n8n
        ↓
    Service C

This makes the architecture easier to debug and replace.

n8n’s HTTP Request node can call REST APIs and supports predefined or
generic authentication methods including API keys, headers, bearer auth
and OAuth2.

Official n8n HTTP Request documentation:
https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.httprequest/

9. n8n Workflow Structure

Use several smaller workflows instead of one giant workflow.

Recommended workflows:

1.  Creator Onboarding
2.  Trend Scanner
3.  Trend Analyzer
4.  Content Factory
5.  Media Factory
6.  Video Renderer
7.  Publishing
8.  Analytics Collector
9.  Learning Engine
10. Error Handler

Each workflow communicates through database records, webhook payloads or
workflow-to-workflow calls.

10. Workflow 1 — Creator Onboarding

Trigger

Frontend sends:

    POST https://YOUR-N8N-DOMAIN/webhook/creator/onboard

n8n Webhook node receives:

    {
      "creator_id": "123",
      "niche": "AI",
      "audience": "students",
      "language": "English",
      "tone": ["fast", "educational"]
    }

n8n nodes

    Webhook
     ↓
    Set / Edit Fields
     ↓
    Supabase Insert Creator
     ↓
    Optional: Download creator examples
     ↓
    Whisper transcription
     ↓
    LLM Creator DNA extraction
     ↓
    Supabase Insert DNA
     ↓
    Respond to Webhook

n8n Webhook nodes can accept authenticated requests and return a
response immediately or after the workflow finishes.

12. Trend Data Structure

Normalize all sources into one format:

    {
      "source": "youtube",
      "external_id": "abc123",
      "title": "New AI Tool Changes Coding",
      "url": "https://...",
      "published_at": "2026-08-17T10:00:00Z",
      "views": 120000,
      "likes": 8500,
      "comments": 1200,
      "topic": "AI coding",
      "collected_at": "2026-08-17T11:00:00Z"
    }

This allows the rest of the system to ignore which source the trend came
from.

24. FFmpeg Architecture

FFmpeg performs:

-   Clip trimming
-   Clip concatenation
-   9:16 conversion
-   Cropping
-   Scaling
-   Overlaying creator video
-   Adding B-roll
-   Captions
-   Logo
-   Text
-   Audio mixing
-   Background music
-   Volume normalization
-   Transitions
-   Final MP4 encoding

The LLM does NOT directly edit the video.

The LLM creates the plan.

FFmpeg executes the plan.

------------------------------------------------------------------------

25. Render Worker

Recommended approach:

    n8n
     ↓
    HTTP Request
     ↓
    Your Render Worker
     ↓
    FFmpeg
     ↓
    Return job ID

The render worker can be:

-   Python + FastAPI
-   Node.js
-   Docker container

Example API:

    POST /render

Body:

    {
      "project_id": "content_123",
      "manifest_url": "https://storage/.../manifest.json"
    }

Response:

    {
      "job_id": "render_456",
      "status": "processing"
    }

n8n then polls:

    GET /render/render_456

until:

    {
      "status": "completed",
      "video_url": "https://storage/.../final.mp4"
    }

38. How n8n Should Connect to APIs

For every REST API:

    HTTP Request Node

Configure:

1.  Method
2.  URL
3.  Authentication
4.  Query parameters
5.  Headers
6.  JSON/body
7.  Response handling

Do not hard-code secrets.

Use n8n Credentials.

Example:

    HTTP Request
    Authentication:
    Bearer Auth

    Header:
    Authorization: Bearer {{$credentials.apiKey}}

n8n supports generic authentication methods such as header, bearer,
OAuth1 and OAuth2 for HTTP requests.

42. Error Handling

Every workflow should include:

    Main operation
          ↓
    IF success
          ↓
    Next stage

    IF failure
          ↓
    Error workflow
          ↓
    Retry / fallback / human review

Examples:

API timeout

Retry with increasing delay.

Rate limit

Wait and retry.

AI invalid JSON

Run JSON validator → repair once → fallback model.

Video generation failure

Use stock/creator footage fallback.

FFmpeg failure

Save logs → identify failed scene → rerender.

Publishing failure

Check publication status before retrying to avoid duplicates.

Fact-check failure

Stop automatic publishing and request approval.

44. Security

-   Store API keys in n8n Credentials.
-   Never expose API keys in frontend JavaScript.
-   Store OAuth tokens securely.
-   Keep creator media private.
-   Use authenticated webhooks.
-   Validate all incoming webhook data.
-   Use HTTPS.
-   Separate development and production credentials.
-   Maintain audit logs.
-   Do not put secrets into LLM prompts.
-   Give each service only the permissions it needs.

------------------------------------------------------------------------

45. Copyright and Content Rules

ViralFlow should:

-   Create original scripts.
-   Avoid copying viral videos.
-   Store source URLs.
-   Track stock-media source.
-   Follow stock API license requirements.
-   Use authorized creator likeness/voice.
-   Avoid unauthorized impersonation.
-   Fact-check claims.
-   Keep human approval available.
-   Follow social platform API and automation rules.

52. Core Design Rule

  AI is the brain. n8n is the orchestrator. FFmpeg/Remotion are the
  hands. APIs provide the senses and external actions. Supabase stores
  the memory.

Do not make ViralFlow dependent on one AI video model.

The strongest hackathon architecture is a modular pipeline where the AI
decides what should happen and deterministic tools execute it.

------------------------------------------------------------------------

53. Final Pitch

  ViralFlow AI doesn’t just generate videos. It decides what a creator
  should make, creates it in their style, publishes it, learns from
  audience response, and uses that learning to decide what to make next.

Core Differentiator

Most AI content tools:

    Prompt → Content

ViralFlow:

    Real-world trends
          ↓
    AI opportunity detection
          ↓
    Creator-specific decision
          ↓
    Autonomous production
          ↓
    Publishing
          ↓
    Real performance
          ↓
    Learning
          ↓
    Better next decision

This closed loop is the product.
